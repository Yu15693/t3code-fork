# 自用构建禁用更新

## 目标与方案

自用 macOS 桌面包保留本地补丁，由维护者选择稳定版、重新构建并手动安装，避免应用内更新用官方版本替换自建版本。

[DesktopUpdates](../../apps/desktop/src/updates/DesktopUpdates.ts) 在没有更新源时将更新状态设为 `disabled`，跳过更新器初始化和定时检查，并拒绝检查、下载和安装操作。本补丁复用这条路径：包内不存在 `app-update.yml`、未启用 mock 更新源、也没有组织策略的 `feedUrl` 时，即视为没有更新源。

在 [构建脚本](../../scripts/build-desktop-artifact.ts) 的 `createBuildConfig` 返回前固定设置 `publish: null`，覆盖 `T3CODE_DESKTOP_UPDATE_REPOSITORY`、`GITHUB_REPOSITORY` 或 mock 配置提供的更新源。保留上游的配置拼装以减少 Fork 差异；最终交给 electron-builder 的配置始终不含更新源，普通桌面启动也不依赖终端环境变量。

## 取舍与范围

- 现有 `T3CODE_DISABLE_AUTO_UPDATE` 是运行时环境变量，只在打包终端设置不会固化到成品，本方案不依赖它。
- 自用环境不配置组织策略的 `feedUrl`，也不启用运行时 mock 更新源；这两项都会绕过“包内无更新源”的前提。
- 桌面托管服务的[更新请求](../../apps/server/src/cloud/selfUpdate.ts)转交桌面应用，因此随桌面包一起覆盖。独立 `t3` 后台服务和 Provider CLI 的更新不属于本补丁范围。

## 验证方式

源码层面最小修改现有[构建测试](../../scripts/build-desktop-artifact.test.ts)：正式版本原本期待的 GitHub 更新源改为 `null`，保留预览版本检查。升级时核对上述“没有更新源即禁用”的判断条件和 `createBuildConfig` 的返回路径仍然成立。

安装包层面确认产物中没有 `app-update.yml`，从 Finder 或 Dock 启动并重启后更新状态为禁用、没有检查或下载行为，且本地服务来自自建包。

## 移除条件

切回官方应用，或上游提供经过成品验证的等效配置时，不再迁移本补丁。
